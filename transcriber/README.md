# transcriber

> **This project is completely vibecoded slop.** Every line was generated by
> an AI coding agent through prompt-driven iteration, with minimal human review.

A small, standalone HTTP service that turns audio/video into text with
[faster-whisper](https://github.com/SYSTRAN/faster-whisper). It lives in the
`transcriber/` directory of this repo but is deliberately independent of the
summarizer app next to it: run it anywhere, call it over HTTP, and point several
clients at the same instance.

- Local only — audio never leaves the machine, no API key, ~99 languages.
- Uses a GPU automatically when CTranslate2 can see one (NVIDIA **or** AMD
  ROCm), otherwise CPU.
- Serialises transcriptions, so concurrent requests queue instead of fighting
  over one GPU.
- Tiny API plus a drag-and-drop page for people who don't want `curl`.

## Install

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-transcribe.txt
```

On an AMD GPU, also swap the CUDA-only CTranslate2 wheel for the official ROCm
one (see [AMD GPU](#amd-gpu-rocm)):

```bash
PYTHON=.venv/bin/python scripts/install_ct2_rocm.sh
```

The first transcription downloads the model (~1.6 GB for `large-v3-turbo`) to
the Hugging Face cache.

## Run

```bash
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8100
# or, using HOST/PORT from .env:
.venv/bin/python -m app.main
```

Check it:

```bash
curl -s localhost:8100/health | python -m json.tool
# {"status":"ok","engine_available":true,"model":"large-v3-turbo",
#  "device":"cuda","compute_type":"float16","batch_size":16,"gpu":true,...}
```

Open <http://localhost:8100/> for the upload page.

## Run as a service (systemd)

`deploy/transcriber.service` is a **user** service — no root needed, and it must
run as you to reach the AMD GPU groups and your Hugging Face model cache:

```bash
mkdir -p ~/.config/systemd/user
ln -sf "$PWD/deploy/transcriber.service" ~/.config/systemd/user/transcriber.service
loginctl enable-linger "$USER"                 # keep running at boot w/o login
systemctl --user daemon-reload
systemctl --user enable --now transcriber.service
```

The unit runs `python -m app.main`, so the bind address and every other setting
come from `.env` (`HOST`, `PORT`, `DATA_DIR`, …). Its absolute paths assume this
checkout lives at `~/summarize2/transcriber`; edit the `Documentation`,
`WorkingDirectory` and `ExecStart` lines if it does not. It restarts on failure
with rate-limiting disabled, so if the address in `HOST` is not up yet at boot,
it just keeps retrying until the bind works.

```bash
systemctl --user status transcriber.service     # state + recent logs
journalctl --user -u transcriber.service -f     # follow logs
systemctl --user restart transcriber.service    # after editing .env or code
systemctl --user disable --now transcriber.service
```

For a **system-wide** unit instead (needs `sudo`): copy the file to
`/etc/systemd/system/`, replace `%h` with your absolute home path, add
`User=you`, and change `WantedBy=default.target` to `multi-user.target`.

## API

### `POST /jobs` — queue a file (recommended)

```bash
curl -s -F file=@lecture.mp4 -F language=it localhost:8100/jobs
# {"id":"a1b2c3d4e5f6","status":"queued","queue":1}
```

Poll status, then fetch the transcript:

```bash
curl -s localhost:8100/jobs/a1b2c3d4e5f6 | python -m json.tool
curl -s localhost:8100/jobs/a1b2c3d4e5f6/transcript -o lecture.txt
```

`GET /jobs/{id}` returns `status` (`queued` / `running` / `done` / `error`), the
detected `language`, audio `duration`, segment/char counts, `elapsed`, and a
tail of the progress `log`. `409` is returned if you ask for the transcript
before the job is `done`. Transcripts are also written to
`DATA_DIR/jobs/<id>/transcript.txt`, so they survive a restart.

### `POST /transcribe` — synchronous

```bash
curl -s -F file=@clip.m4a localhost:8100/transcribe
# {"text":"...","language":"en","duration":42.0,"segments":3,"chars":210,...}
```

Blocks until the file is done; fine for short clips, use `/jobs` for long ones.

### Other endpoints

| method | path | purpose |
|---|---|---|
| `GET` | `/health` | engine + queue status |
| `GET` | `/jobs` | recent jobs (`?limit=`) |
| `GET` | `/jobs/{id}` | status, log, metadata |
| `GET` | `/jobs/{id}/transcript` | transcript as `text/plain` |
| `GET` | `/` | drag-and-drop page |

`language` is an optional ISO-639-1 code (`it`, `en`, …); omit it to
auto-detect.

## Security

There is **no authentication** built in. Bind to `127.0.0.1` unless the
machine is reachable only on a network you trust; to expose it, put it behind
your own reverse proxy or VPN.

## AMD GPU (ROCm)

CTranslate2 ships ROCm wheels since v4.7.1, so no source build is needed. Needs
ROCm installed, `/dev/kfd` accessible, and your user in the `video` and `render`
groups:

```bash
.venv/bin/pip install -r requirements-transcribe.txt
PYTHON=.venv/bin/python scripts/install_ct2_rocm.sh
.venv/bin/python -c "import ctranslate2; print(ctranslate2.get_cuda_device_count())"  # -> 1+
```

CTranslate2 still calls the device `cuda` on ROCm, so `TRANSCRIBE_DEVICE=auto`
just works. The engine also forces `CT2_CUDA_ALLOCATOR=cub_caching`, because the
default allocator hits `Memory access fault by GPU node` on AMD for audio longer
than ~a minute. Roll back to the CUDA wheel with
`.venv/bin/pip install --force-reinstall ctranslate2`.

Batched decoding (`TRANSCRIBE_BATCH_SIZE`, default 16) decodes many VAD segments
in parallel; on an RX 7600 that measured **~75× realtime** vs ~11× sequential.

## Configuration

Copy `.env.example` to `.env` to override. Everything is optional.

| variable | default | meaning |
|---|---|---|
| `DATA_DIR` | `./data` | uploads + finished transcripts |
| `HOST` / `PORT` | `127.0.0.1` / `8100` | bind address / port |
| `TRANSCRIBE_MODEL` | `large-v3-turbo` | Whisper model name |
| `TRANSCRIBE_DEVICE` | `auto` | `auto` / `cpu` / `cuda` |
| `TRANSCRIBE_COMPUTE_TYPE` | `auto` | `float16` on GPU, `int8` on CPU |
| `TRANSCRIBE_BATCH_SIZE` | `16` | parallel VAD segments; `0` = sequential |
| `MAX_FILE_MB` | `2000` | per-request upload cap |
| `JOB_TTL_HOURS` | `24` | prune finished jobs after this long; `0` = keep |

## How it works

`app/engine.py` wraps faster-whisper with a **cross-process** `filelock` on
`DATA_DIR/transcribe.lock`: only one transcription runs at a time machine-wide,
because two jobs on one GPU can exhaust VRAM and a GPU memory fault is
process-fatal. `app/main.py` adds a single background worker (so a queue of
requests runs FIFO) and the HTTP surface above.

If the batched pipeline ever fails, the job transparently retries sequentially.
